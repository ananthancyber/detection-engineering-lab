## 1. Validation Overview

Rule 007 was developed to detect enumeration of the local **Administrators** security group through `net1.exe`.

The detection was developed using a telemetry-driven approach rather than alerting on every Windows Event ID 4799.

Initial analysis identified a large volume of legitimate 4798/4799 activity generated by Windows services, system processes, and security tooling. Process-level analysis identified `net1.exe` as a distinct discovery-related process associated with an `Administrator` account.

A controlled discovery test was then performed using Windows built-in commands. The resulting Windows Security Event ID 4799 was successfully ingested into Splunk and matched by the final detection query.

The validation chain was:


# 2. Detection Objective

The objective of Rule 007 is to identify local **Administrators group enumeration** performed through `net1.exe`.

The detection focuses on the combination of:

- Windows Security Event ID `4799`
- Group name `Administrators`
- Process name ending in `net1.exe`

This focused approach reduces unnecessary detection noise compared with alerting on every Event ID 4799.

---

# 3. Detection Scenario

The validated behavior represents local permission-group discovery.

The controlled activity used:

~~~powershell
net user

net localgroup

net localgroup Administrators
~~~

The final command specifically enumerated members of the local `Administrators` group.

This generated a Windows Security Event ID 4799 indicating:

~~~text
A security-enabled local group membership was enumerated.
~~~

# 12. Rule 007 SPL Detection

The final Splunk detection was created at:

~~~text
splunk-queries/discovery/administrators-group-enumeration.spl
~~~

Detection logic:

~~~spl
index=main sourcetype="WinEventLog:Security" EventCode=4799
| rex field=_raw "Account Name:\s+(?<SubjectAccount>[^\r\n]+)"
| rex field=_raw "Group Name:\s+(?<GroupName>[^\r\n]+)"
| rex field=_raw "Group Domain:\s+(?<GroupDomain>[^\r\n]+)"
| rex field=_raw "Process Name:\s+(?<ProcessName>[^\r\n]+)"
| search ProcessName="*net1.exe" GroupName="Administrators"
| eval Detection="Administrators Group Enumeration via net1.exe"
| table _time host SubjectAccount GroupName GroupDomain ProcessName EventCode Detection
| sort - _time
~~~

The detection requires:

~~~text
EventCode = 4799
        AND
GroupName = Administrators
        AND
ProcessName = net1.exe
~~~

This provides a focused detection rather than alerting on all Windows group enumeration events.

# 16. Detection Quality Assessment

The detection was intentionally narrowed after reviewing the baseline.

A generic detection such as:

~~~spl
EventCode=4799
~~~

would match hundreds of events in the current environment.

The validated Rule 007 instead requires:

~~~text
4799
+
Administrators
+
net1.exe
~~~

This approach demonstrates practical detection engineering by considering:

- Existing telemetry volume
- Legitimate background activity
- Process context
- Account context
- Privileged group context
- Controlled validation results

The detection is therefore designed around a specific, observable behavior rather than a single high-volume event type.

# 17. SOC Investigation Perspective

A detection involving enumeration of the local Administrators group can provide useful context during a SOC investigation.

An analyst receiving this detection should investigate:

1. **Who performed the enumeration?**
   - Subject account
   - Security identifier
   - Domain

2. **Which group was enumerated?**
   - Group name
   - Group domain

3. **Which process performed the enumeration?**
   - Process name
   - Process ID where available

4. **Was the activity expected?**
   - Administrative troubleshooting
   - IT support
   - Security assessment
   - Endpoint management

5. **What occurred before the enumeration?**
   - Authentication events
   - Process creation
   - Privilege changes

6. **What occurred afterward?**
   - Account manipulation
   - Privilege escalation
   - Process execution
   - Additional discovery activity

The detection should therefore be treated as a **security investigation signal**, with surrounding telemetry used to determine the context of the activity.
