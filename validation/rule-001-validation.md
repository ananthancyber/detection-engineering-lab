## Objective

Validate that the first Sigma detection identifies Windows failed authentication attempts recorded as Security Event ID `4625`.

The purpose of this validation is to confirm that:

- Windows Security Event ID `4625` is available in Splunk Cloud.
- The detection logic identifies failed logon events.
- Useful authentication fields can be investigated.
- The matching SPL query returns relevant security telemetry.
- The detection limitations and false-positive conditions are documented.

## Lab Environment

- **Host Operating System:** Windows 11
- **Windows Endpoint:** WIN10-CLIENT
- **Domain:** CORP / CORP.LOCAL
- **SIEM:** Splunk Cloud
- **Log Collector:** Splunk Universal Forwarder
- **Log Source:** Windows Security Event Log
- **Data Source:** `WinEventLog:Security`

## Detection Logic

The Sigma rule detects Windows Security events where:

~~~text
EventID = 4625
~~~

Windows Event ID `4625` represents a failed logon attempt.

The rule detects the underlying authentication failure but does not independently confirm that the activity is malicious.

## Sigma Rule

~~~yaml
title: Windows Failed Logon Attempt
id: 7f2c9d1e-4625-4a6b-9f31-001fa1ed0a01
status: experimental
description: Detects failed Windows authentication attempts recorded by Security Event ID 4625.
author: Ananthan D
date: 2026/09/18

logsource:
  product: windows
  service: security

detection:
  selection:
    EventID: 4625
  condition: selection

falsepositives:
  - Incorrect user password
  - User entering an invalid username
  - Expired or locked account
  - Misconfigured services
  - Legitimate administrative activity

level: low

tags:
  - attack.credential_access
  - attack.t1110
~~~

## Splunk Validation Query

~~~spl
index=main sourcetype="WinEventLog:Security" EventCode=4625
| stats count by Account_Name, Account_Domain, Source_Network_Address, Logon_Type, host
| sort - count
~~~

## Important Findings

### Finding 1 — Failed Authentication Telemetry Confirmed

Splunk Cloud successfully received Windows Security Event ID `4625` from `WIN10-CLIENT`.

### Finding 2 — Non-Local Source Observed

The source address `192.168.159.129` generated failed logon events involving:

- `bh_enum`
- `pt_test`

This activity is considered **suspicious authentication telemetry**, but it is not classified as a confirmed attack based on this event alone.

### Finding 3 — Network Logon Activity

The observed events used:

~~~text
Logon Type: 3
~~~

Logon Type `3` represents a network logon attempt.

### Finding 4 — Field Extraction Inconsistency

Some events displayed `-` for fields such as:

- `Account_Name`
- `Account_Domain`

Although account information was visible in the raw event data, some extracted fields were incomplete or inconsistent.

This demonstrates that detection rules must be tested against actual telemetry and should not depend exclusively on one extracted field.

## Detection Result

**PASS — The detection successfully identified Windows Event ID 4625 events in Splunk Cloud.**

The validation confirms that:

- The Windows Security logs are available.
- Event ID `4625` is searchable.
- The Sigma detection logic matches the event type.
- The corresponding SPL query returns relevant results.
- Authentication activity can be investigated using account, source, logon type, and host information.

## Detection Limitation

This rule detects individual failed logon events.

It does not yet determine whether the activity represents:

- Brute force
- Password spraying
- Account misuse
- Service misconfiguration
- A legitimate user mistake

Additional correlation logic is required to detect repeated failed logons within a defined time window.

## False-Positive Considerations

Potential legitimate causes include:

- Incorrect user passwords
- Invalid usernames
- Expired accounts
- Locked accounts
- Misconfigured services
- Machine-account authentication failures
- Legitimate administrative activity
- Local system authentication activity

## MITRE ATT&CK Mapping

### T1110 — Brute Force

Failed logon events can provide telemetry for investigating brute-force activity.

However, the presence of Event ID `4625` alone does not prove that a brute-force attack occurred.

The next detection improvement will use:

- Multiple failed logons
- A common source IP
- A defined time window
- Multiple targeted accounts
- Threshold-based correlation

## Conclusion

The first Sigma detection was created and validated against real Windows Security telemetry in Splunk Cloud.

The detection successfully identifies Event ID `4625` failed-logon activity. The investigation also identified inconsistent field extraction and suspicious authentication activity from the lab source IP `192.168.159.129`.
